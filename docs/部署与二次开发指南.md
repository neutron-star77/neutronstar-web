## 1. 架构总览

```
浏览器
  └─ neutronstar.fun  (Cloudflare Pages 项目 neutronstar-web，由本仓库构建)
       ├─ Astro 静态壳 + 侧栏 (Sidebar/Shell, Astro 组件)
       ├─ React islands (client:visible 水合): MomentsList / AlbumGrid / AlbumDetail / HomeFeed / PostList / PostView
       └─ 数据走 bff.neutronstar.fun  (Hono on Cloudflare Workers, 仓库 worker-bff)
            ├─ /api/*         → 回源后端 kirameku-api.neutronstar.fun (FastAPI, NAS 隧道)
            ├─ /bff/home      → 聚合(文章数/说说数/照片数)
            ├─ /img?w=        → 图片边缘优化 (AVIF/WebP, 缓存)
            └─ /internal/revalidate (HMAC + KV tag 失效)
```

要点：
- 前端**不写死内容数据**，一律经 HTTP API（`bff`）取。
- 相册是**例外**：数据走前端静态 `src/data/albums.ts`（鬼刀图床 jsDelivr，6 册 234 张），因为后端 `albums` 为空。
- 动效用 `motion` v13（`motion/react`，即 Framer Motion 新包名），统一变体集中在 `src/lib/variants.ts`。

## 2. 本地开发

```bash
cd web
pnpm install          # 需要 Node >= 22.13（package.json engines 限制）
pnpm dev              # astro dev → http://localhost:4321
pnpm build            # 生产构建到 dist/（SSG + client:visible islands）
pnpm preview          # 本地预览构建产物
```

环境变量（可选）：
- `PUBLIC_API_BASE`：API 前缀，默认兜底 `https://bff.neutronstar.fun`（`src/lib/api/client.ts`）。
- `astro` 类型：`pnpm exec astro sync` 生成 `.astro/types`。

> 注：`astro check`（类型检查）需要额外装 `@astrojs/check`，未预装。改动后用 `pnpm build` 即可（Vite 会编译所有 island，能抓到导入/JSX/类型错误）。

## 3. 部署链路（自动）

- 仓库：`neutron-star77/neutronstar-web`，分支 `main`，CF Pages 项目名 `neutronstar-web`。
- 触发：`git push origin main` → GitHub Actions 跑 `.github/workflows/deploy.yml`。
- 流程：checkout → 装 pnpm → `pnpm install --frozen-lockfile` → `pnpm build` → `pnpm dlx wrangler@3 pages deploy dist/client --project-name neutronstar-web --branch main`。
- Secrets（仓库 Settings → Secrets）：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。
- 构建命令必须是 `pnpm build`（package.json 有 `only-allow pnpm`，用 npm 会被拦）。
- 输出目录：`dist/client`（Astro + `@astrojs/cloudflare` 适配器）。

后台配置：

- `navigation`：主导航和二级菜单；
- `music_widget`：音乐悬浮卡片；
- `sidebar_widgets`：作者、导航、公告、分类、标签、日历卡片开关。

手动部署（备用，需 `CLOUDFLARE_ACCOUNT_ID` 环境变量）：
```bash
$env:CLOUDFLARE_ACCOUNT_ID="d4add8ad549536a77a5b9fcf6d5be733"
pnpm dlx wrangler@3 pages deploy "dist/client" --project-name neutronstar-web --branch main
```

## 4. 坑点汇总（都是实测过的）

### 4.1 pnpm 版本锁冲突（CI 第一次速败）
`package.json` 有 `packageManager: pnpm@11.22.0`。CI 里 `pnpm/action-setup@v4` **不要写 `version:`**（否则默认装 v9，与 `packageManager` 冲突报错）。
✅ 当前 deploy.yml 已去掉 `version:`，直接 `pnpm/action-setup@v4` 即可。

### 4.2 CF Pages Git 集成 webhook 失效
某次 push 后 CF Pages 没自动构建（部署列表停在旧时间）。诊断：仓库 `webhooks=[]`（CF GitHub App 集成失效）。
✅ 改用 **GitHub Actions** 双保险接管部署（见 §3）。CF Git 集成后来又恢复，但 Actions 仍是主链路。

### 4.3 `wrangler pages deploy` 报 400 / code 9106
用 Account API Token 直跑 `wrangler pages deploy --account-id <id>` 会走 `/memberships` 报 400。
✅ 去掉 `--account-id` flag，改设环境变量 `CLOUDFLARE_ACCOUNT_ID`（不带 flag）。

### 4.4 CF API Token 权限不足（只读 token）
只读 token 能通过 `/tokens/verify`（看起来"有效"），但 `wrangler kv namespace create` / `wrangler deploy` 会失败。
✅ 需要的权限：`Account:Workers Scripts:Edit` + `Account:Workers KV Storage:Edit` + `Zone:DNS:Edit`（neutronstar.fun）。
✅ 已建 KV：`CACHE_TAGS` id `4959a742fe4d44dbbc0ba8c200bea694`（worker-bff 用）。
⚠️ token 仅命令内联使用，用完建议轮换；已存 GitHub Secret 的同理。

### 4.5 根域"明明部署了却还是旧内容"——Worker route 抢占
切 Pages 自定义域后，若"绑定 active + DNS 正确 + purge 了仍命中旧构建"，根因常是 **zone 里残留同名子域的 Cloudflare Worker route 抢流量**（`sub.domain/* → 某 Worker`），优先级高于 Pages。
✅ 诊断：`wrangler routes list` / `GET /zones/{zone}/workers/routes`；修复=删抢占 route + purge cache。
⚠️ 切根域（T10，见 §7）时必须先查 `neutronstar.fun` 的 zone 有没有 Worker route 抢占。

### 4.6 根域仍是旧 Vite SPA（当前"首页不一致"主因）
`neutronstar.fun` 现在指向旧的 `NeutronStar 星舰`（Vite SPA），不是新 Astro 站。新站在 `neutronstar-web.pages.dev`。
✅ 修复 = T10 切根域（§7）。在此之前，验证新站请直接用 `neutronstar-web.pages.dev`。

### 4.7 相册 / 说说数据来源不同，别搞混
- **说说**：`useChatters()` → 真实后端。后端若没数据，页面显示"还没有动态"（动画只在有内容时可见）。
- **相册**：`src/data/albums.ts` 静态（鬼刀图床 jsDelivr）。后端 `albums` 为空，所以相册不走 bff。改相册数据改这个文件，或改 `AlbumGrid` 接 `useAlbums()`。

### 4.8 别用 `git add -A`
曾因 `git add -A` 把后端/worker-bff/docs 的 WIP 一起打包进相册提交，回退时只能外科手术式逐个文件还原（commit `2310a4e`）。
✅ 提交前端改动只 `git add` 指定文件。

## 6. 动画调参速查（二次开发最常改）

| 想调什么 | 文件 / 位置 |
|---|---|
| 说说同日卡片倾斜角 | `src/lib/variants.ts` → `stackRotations`（固定序列，确定性） |
| 说说弹簧手感 | `MomentsList.tsx` 内联 `spring 300/25`，或改 `variants.ts` 的 `spring.card` |
| 相册封面扇形角度 | `AlbumGrid.tsx` 顶部 `STACK_ANGLES / FAN_ANGLES / FAN_Y` |
| 拍立得照片倾斜角 | `src/lib/variants.ts` → `tiltFromId(id)`（±2.4°，按 id 派生，**禁止随机**） |
| 灯箱缩放手感 | `Lightbox.tsx` 图片 `motion.div` 的 `spring 300/25` |
| 进场 fade-up | `src/styles/animations.css` + `variants.ts` 的 `fadeUp/cardIn` |
| 主题色(token) | Tailwind 配置里的 primary/secondary/surface（见 globals / tailwind 配置） |

通用约定（来自 `variants.ts` 头部）：
- 只动 `transform / opacity`，避免触发布局重排（保 CLS）。
- `reduced-motion` 由 `motion` 的 `MotionConfig` 统一降级，组件不各自判断。
- 随机倾斜必须由 **id 确定性派生**，禁止 `Math.random()`（否则 SSR/水合不一致、每次刷新角度乱跳）。

## 7. 常见二次开发任务

### 7.1 加"说说评论" / 持久化点赞（需后端）
当前点赞是**前端乐观态**（未落库）。要真实评论/点赞：
1. `worker-bff` 加 `POST /api/chatters/{id}/comments`（及可选 `POST /api/chatters/{id}/like`）。
2. 前端 `MomentsList.tsx` 加评论区，用 SWR `mutate` 更新；参考原版 `Kirameku-ref/components/comments/`（含 GitHub OAuth 登录）。
3. GitHub OAuth：在 bff 加 `/auth/github` 回调，前端存 token 调接口。

### 7.2 改相册数据源
- 换图床/分组：直接编辑 `src/data/albums.ts`（jsDelivr 链接，每册 39 张，分 6 册 `guidao-1..6`）。
- 接真实后端：把 `AlbumGrid.tsx` 顶部的 `import { albums }` 换成 `const { data: albums } = useAlbums()`（`hooks.ts` 已有 `useAlbums`）。

### 7.3 改说说取数
`hooks.ts` 的 `useChatters({ page, size })`；字段结构见 `types.ts` 的 `Chatter`（content / images / mood / likes / created_at）。

### 7.4 切根域（T10，解决"首页不一致"）
1. `neutronstar.fun` DNS CNAME → `neutronstar-web.pages.dev`。
2. CF Pages 项目加自定义域 `neutronstar.fun` 并等绑定 active。
3. **先查 zone 有没有 `neutronstar.fun` 的 Worker route 抢占**（§4.5），有则删。
4. purge 全站缓存。
⚠️ 需要 CF Token 含 `Zone:DNS:Edit`（neutronstar.fun）。

### 7.5 换导航/社交/作者
`src/config/site.ts`（nav / social / author / tagline）。
